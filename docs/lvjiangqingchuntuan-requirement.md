# 驴酱青春团 · 团播温度值看板 需求设计文档

> 页面路径：`{baseUrl}/lvjiangqingchuntuan`
> 默认房间：`317422`（驴酱青春团）
> 状态：已合入第一轮评审反馈（v2），待确认后进入开发

## 1. 需求理解与背景

驴酱青春团团播期间，老板通过弹幕给团员发放/炸掉「温度值」。当前通用监控页只能按关键词抓取弹幕，无法区分「指令是否被小助手确认生效」，主播/场控无法快速判断哪些指令已被处理。

本需求新增一个**专用看板页**：实时抓取房间内符合规则的给分/炸分指令弹幕，并在收到「新驴酱团播小助手」的确认回复后，为对应指令打上**绿色对勾（有效标记）**，形成一块供主播/场控实时查看、核对指令处理情况的看板。

### 1.1 核心业务流程

```
老板发送指令弹幕            小助手确认回复
"#给光阴1000"              "@老板昵称，转给光阴1000温度值，剩余1533.4温度值"
      |                            |
      v                            v
+-----------------------------------------------------------+
|  团播看板页（WebSocket 实时接收 chatmsg）                  |
|                                                           |
|  1. 指令弹幕抓取：命中 #给 / #炸 规则 → 生成指令条目        |
|     状态 = 待确认（黄色时钟）                              |
|  2. 小助手回复抓取：昵称为「新驴酱团播小助手」的弹幕         |
|     → 解析回复（老板昵称 / 团员名 / 数值 / 剩余额度）        |
|  3. 关联匹配：在待确认队列中找到对应指令                    |
|     → 该指令状态 = 有效（绿色对勾 ✓）                      |
|  4. 超时兜底：超过确认窗口仍无回复                          |
|     → 该指令状态 = 未确认（灰色，不再参与匹配）              |
+-----------------------------------------------------------+
```

### 1.2 需求确认结论（已与需求方对齐）

| 事项 | 结论 |
|------|------|
| 页面范围 | **仅团播看板**，不保留普通弹幕/礼物/进场/超级弹幕等模块 |
| 温度聚合统计 | **暂不需要**，不做团员温度排行与净温度计算 |
| 炸分语义 | **仅展示**，不参与任何数值统计（本版无统计功能） |
| 确认回复格式 | 给分（`转给`）与炸分（`炸`）确认样例均已确认（见 3.3.1） |
| 页面用途 | 供主播/场控在浏览器中查看，**不面向直播伴侣叠加使用**（无需背景透明、分享链接） |
| 特殊团员名 | 存在纯数字昵称（如 `145`），需按「团员名单」消歧，避免识别错误或遗漏（见 3.2） |
| 优化项 | 「点击置灰/自动移除」「确认耗时展示」均**保留** |

## 2. 名词定义

| 名词 | 定义 |
|------|------|
| 老板 | 发送给分/炸分指令弹幕的观众（不限制等级，任何用户均可发送） |
| 团员 | 被给分/炸分的团播成员 |
| 给分指令 | 形如 `#给{团员名}{温度值}` 的弹幕，例如 `#给光阴1000` |
| 炸分指令 | 形如 `#炸{团员名}{温度值}` 的弹幕，例如 `#炸光阴1000` |
| 温度值 | 指令中携带的数值（给分/炸分均只作展示，本版不做累计） |
| 团播看板 | 本页面唯一展示模块：给分/炸分指令流水 + 状态标记 |
| 团员名单 | 可在配置中维护的团员昵称列表，用于解析消歧（见 3.2） |
| 确认回复 | 昵称为「新驴酱团播小助手」的账号发出的回复弹幕 |
| 待确认 / 有效 / 未确认 | 指令条目的三种状态，详见 3.3.3 |

## 3. 功能需求

### 3.1 页面入口与房间

- 页面路径：`{baseUrl}/lvjiangqingchuntuan`，访问该路径进入团播看板页（单页应用内路由，与现有监控页互不影响）。
- 默认房间号：`317422`；进入页面后自动连接该房间的弹幕服务器。
- 房间号覆盖：支持通过 `?rid={房间号}` 覆盖默认值（用于房间变更或调试）。
- 页面标题：`驴酱青春团 - 团播温度值看板`。
- 连接状态：沿用现有左上角连接状态指示（已连接 / 连接中），便于确认弹幕连接是否正常。

### 3.2 指令弹幕抓取

- **抓取范围**：房间内**所有用户**的弹幕，不受普通弹幕的等级/关键词/昵称屏蔽规则影响。
- **匹配规则**：弹幕文本以 `#给`（给分）或 `#炸`（炸分）开头。
- **解析规则**（按优先级）：

  | 优先级 | 规则 | 示例 |
  |--------|------|------|
  | 1 | **团员名单优先匹配**：去除前缀后，将文本开头与「团员名单」中的昵称比对（从最长昵称开始尝试）；若命中且昵称之后的剩余部分为「可选空格 + 数字（含小数）」，则 团员名 = 命中的昵称，温度值 = 剩余数字 | 名单含 `145` 时：`#给1451000` → 团员名 `145`、温度值 `1000` |
  | 2 | **通用回退解析**：未命中名单时，取文本末尾连续数字（含小数）为温度值，其余去除首尾空格后为团员名 | `#给光阴1000` → 团员名 `光阴`、温度值 `1000` |
  | 3 | **解析失败丢弃**：无法得到有效团员名（如 `#给1000`）的弹幕不生成条目，仅记录控制台日志 | `#给1000` → 丢弃 |

- **团员名单说明**：
  - 名单仅用于**解析消歧**，不做过滤——未在名单中的团员指令仍按通用规则解析，保证新团员指令**不遗漏**。
  - 名单可在配置页维护（默认预置 `145`），后续有新的纯数字/含数字昵称时补充即可。
  - 纯数字昵称（如 `145`）若不在名单中，通用规则会把昵称数字并入温度值导致识别错误，因此该类昵称**必须**加入名单。
- **展示时机**：抓取到即展示（状态为「待确认」），不等待确认回复。

### 3.3 有效性确认规则（核心）

#### 3.3.1 确认回复解析

以「新驴酱团播小助手」为发送者的弹幕为候选确认回复。已确认格式（样例由需求方提供）：

| 类型 | 回复原文样例 |
|------|-------------|
| 给分确认 | `@我松洞了，转给豆包2000温度值，剩余1533.4温度值` |
| 给分确认 | `@小牛啃草，转给醋醋100温度值，剩余2.1温度值` |
| 炸分确认 | `@新驴酱丶张顺飞，炸白晶晶1温度值，剩余0.5温度值` |

解析字段：

| 字段 | 解析方式 | 样例（炸分）结果 |
|------|---------|----------------|
| 老板昵称 | `@` 之后至首个逗号/冒号之前的文本 | 新驴酱丶张顺飞 |
| 指令类型 | 文本含 `转给` → 给分；含 `炸` → 炸分 | 炸分 |
| 团员名 / 数值 | 关键词与 `温度值` 之间的文本，按「团员名单优先、通用回退」切分（同 3.2） | 白晶晶 / 1 |
| 剩余额度 | `剩余` 之后至 `温度值` 前的数字 | 0.5 |

- 回复需同时包含 `温度值` 与 `剩余` 才视为候选确认回复；无法匹配的助手弹幕不参与标记（见 3.3.3）。
- 解析需兼容斗鱼「回复」样式可能携带的前缀（如 `回复@某某：`）与中英文逗号/冒号。
- 团员名单同样参与回复解析消歧：如 `转给1451000温度值` → 团员 `145`、数值 `1000`。
- 当前为**给分/炸分两类模板**，已由样例覆盖。若后续出现其它回复模板（如「余额不足/拒绝」），按同样方式扩展（见第 7 节）。

#### 3.3.2 关联匹配优先级

一条确认回复**只标记一条指令**，标记后该指令移出待确认队列。按以下优先级依次尝试，命中即止：

| 优先级 | 匹配条件 | 说明 |
|--------|---------|------|
| 1 | 老板昵称 + 团员名 + 数值 全一致 | 未确认队列中该老板最近一条相同指令 |
| 2 | 老板昵称 + 团员名 一致 | 该老板最近一条未确认指令 |
| 3 | 老板昵称 一致 | 该老板最近一条未确认指令（团员名解析失败时兜底） |
| 4 | 团员名 + 数值 一致 | 仅当回复中解析不出老板昵称时使用（全房间范围，最近一条） |
| 5 | 以上均未命中 | 不做任何标记，仅记录原始消息到控制台日志，便于排查与模板扩展 |

> 参与匹配的团员名/数值均为「名单消歧后」的解析结果。
> **设计原则：宁可不标记，不可错标记。** 任何不确定情形均不改变指令状态，保证绿色对勾的准确性。

#### 3.3.3 状态流转

| 状态 | 触发条件 | 标记 | 是否参与后续匹配 |
|------|---------|------|----------------|
| 待确认 | 抓取到指令弹幕（初始状态） | 黄色时钟图标 + 「待确认」 | 是 |
| 有效 | 命中确认回复并匹配成功 | **绿色对勾** ✓ | ——（已出队） |
| 未确认 | 超过确认窗口（默认 60 秒）仍无匹配回复 | 灰色标记（条目整体淡化） | 否 |

- 确认窗口默认 **60 秒**，可在配置中调整（见 3.6）。
- 一条指令只会被标记一次；重复回复不会二次标记。
- 助手「余额不足/拒绝」类回复的语义与标记方式：**[TBD] 待补充样例后定义**（当前按第 5 优先级处理——不标记）。

### 3.4 看板展示

**条目结构**（每行一条指令，最新在下，自动滚动到底部，支持「回到底部」）：

```
+------------------------------------------------------------------+
| 老板昵称    #给光阴1000            12:03:45   [⏳ 待确认]          |
+------------------------------------------------------------------+
| 老板昵称    #给光阴1000            12:03:46   [✓ 有效] +3s        |
|             转给光阴 1000 · 剩余 1533.4                           |
+------------------------------------------------------------------+
| 老板昵称    #炸光阴1000            12:05:02   [— 未确认]          |
+------------------------------------------------------------------+
```

- **老板昵称**：指令发送者昵称。
- **指令原文**：完整弹幕文本；`#给` 与 `#炸` 使用不同强调色（默认：给分用暖橙色系、炸分用冷紫蓝色系）。
- **接收时间**：精确到秒。
- **状态标记**：待确认 = 黄色时钟；有效 = 绿色对勾；未确认 = 灰色标记（条目整体淡化）。
- **确认详情**：标记有效后，补充展示回复中解析的「转给数值 / 剩余额度」，便于老板对账。
- **空态提示**：暂无团播指令。
- **消息上限**：沿用全局「消息上限」配置（默认 100 条），超出后移除最旧条目。

**优化项（已确认保留）**：

1. **点击置灰**：点击任意条目可手动置灰表示「已处理」，与现有指令弹幕模块交互一致；可配置开启「自动移除」后按设定秒数删除（默认关闭）。
2. **确认耗时展示**：有效条目显示「指令 → 确认」耗时（如 `+3s`），便于评估小助手响应速度；默认开启，可通过配置关闭。

### 3.5 主题与样式

- 沿用现有日夜主题体系，支持日间/夜间模式切换。
- 沿用字号、动画等通用样式配置。
- 沿用现有模块的滚动条、空态、动画风格，保证项目视觉一致性。

### 3.6 页面配置

配置弹窗仅保留两块内容：

**通用配置（复用现有组件）**：字号、动画、消息上限、主题切换、恢复默认。

> 本页不面向直播伴侣叠加使用，故不提供「背景透明」与「分享链接」配置（评审确认）。

**「团播看板」配置页签**：

| 配置项 | 说明 | 默认值 |
|--------|------|-------|
| 助手昵称 | 确认回复的发送者昵称，支持后续改名 | 新驴酱团播小助手 |
| 团员名单 | 解析消歧用昵称列表（含数字昵称如 145），可添加/删除 | 预置 `145` |
| 确认窗口（秒） | 超过该时长未收到确认回复 → 标记「未确认」 | 60 |
| 确认耗时展示 | 有效条目显示「指令 → 确认」耗时 | 开启 |
| 点击置灰自动移除 | 开启后点击条目按设定时间自动移除 | 关闭 |
| 自动移除时间（秒） | 仅开关开启时可编辑 | 30 |

- **配置存储**：使用独立存储键（与主监控页配置互不影响），配置变更实时保存、实时生效。

## 4. 边界与异常场景

| 场景 | 行为 |
|------|------|
| 纯数字昵称团员（如 `145`） | 名单命中 → 正确解析（`#给1451000` → 团员 `145`、数值 `1000`）；未配置名单时按通用规则解析会错误，因此该类昵称必须加入名单 |
| 团员名含数字且未在名单中 | 按通用规则尽力解析；若无法得到有效团员名则丢弃、不入看板，记录控制台日志 |
| 同一老板连续发送多条相同指令 | 每条指令独立成条；每条确认回复按就近原则标记一条，一一对应 |
| 一条指令收到多条确认回复 | 第一条即标记有效并出队，后续回复按优先级 5 处理（不重复标记） |
| 助手弹幕无法解析 | 不标记任何指令，记录控制台日志 |
| 回复中的团员名/数值与指令不一致 | 降级到更低优先级匹配；仍不匹配则不标记 |
| 弹幕连接断开重连 | 沿用现有重连与心跳机制；断线期间的指令无法补抓（弹幕为实时流） |
| 页面刷新 | 看板数据不持久化，刷新后重新累积（配置保留） |
| 房间号变更 | 通过 `?rid=` 覆盖默认房间号 |

## 5. 技术设计（概要）

### 5.1 路由与页面

- `src/router.js`：识别路径末段 `lvjiangqingchuntuan` → 房间号固定 `317422`（`?rid=` 优先）；输出页面类型标识。
- `src/App.vue`：按页面类型渲染监控页或团播看板页。
- 新增页面：`src/lvjiang/pages/index.vue`（团播看板页，含连接状态、看板列表、配置弹窗）。

### 5.2 模块划分

| 模块 | 职责 | 路径（建议） |
|------|------|-------------|
| 看板主组件 | 列表渲染、滚动、空态、回到底部 | `src/lvjiang/components/Board/Board.vue` |
| 条目模板 | 单条指令渲染（状态标记、确认详情、确认耗时） | `src/lvjiang/components/Board/templates/Default.vue` |
| 看板配置 | 「团播看板」配置页签（含团员名单维护） | `src/lvjiang/components/Board/BoardConfig.vue` |
| 弹幕连接 Hook | 复用现有 `Ex_WebSocket_UnLogin` + STT，处理 chatmsg | `src/lvjiang/hooks/useLvjiangWs.js` |
| 指令解析（纯函数） | `#给/#炸` 解析为 `{ type, member, value }`，含名单消歧 | `src/lvjiang/utils/parseCommand.js` |
| 回复解析（纯函数） | 助手回复解析为 `{ boss, type, member, value, remaining }`，含名单消歧 | `src/lvjiang/utils/parseAssistantReply.js` |
| 关联匹配（纯函数） | 按 3.3.2 优先级在待确认队列中匹配 | `src/lvjiang/utils/matchReply.js` |

### 5.3 核心数据结构

```javascript
// 指令条目
const commandItem = {
  id: 'cid',                 // 弹幕 cid（去重）
  boss: '我松洞了',           // 老板昵称
  type: 'give',              // give=给分 bomb=炸分
  member: '145',             // 团员名（名单消歧后）
  value: 1000,               // 温度值
  rawText: '#给1451000',      // 原始弹幕文本
  timestamp: 1768000000000,  // 接收时间
  status: 'pending',         // pending=待确认 valid=有效 unconfirmed=未确认
  confirmedAt: null,         // 确认时间
  confirmInfo: null,         // 确认详情：{ value, remaining }
  isHandled: false,          // 手动置灰（优化项）
};

// 页面配置（独立存储键）
const lvjiangOptions = {
  assistantName: '新驴酱团播小助手',
  members: ['145'],          // 团员名单（解析消歧）
  confirmTimeout: 60,        // 确认窗口（秒）
  showConfirmCost: true,     // 确认耗时展示
  autoRemoveHandled: false,  // 点击置灰自动移除
  autoRemoveDelay: 30,       // 自动移除时间（秒）
};
```

- 待确认队列：按时间升序的 `pending` 条目集合，匹配成功即出队。
- 看板列表：全部条目（含三种状态），按 `threshold` 截断。

### 5.4 复用与约束

- 复用 `Ex_WebSocket_UnLogin`、STT 反序列化、去重与重连/心跳逻辑，**不新增任何网络请求**。
- 解析与匹配逻辑全部为纯函数（名单作为入参），与 UI 解耦，便于单元测试。
- 独立 `options` 与存储键，避免与监控页配置互相污染。
